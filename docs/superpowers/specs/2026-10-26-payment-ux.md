# 결제 UX 설계 — 두 번 누르면 끝

쿠팡이 두 번이면 우리도 두 번. 우리는 파는 게 하나뿐이라 더 쉽다. 상품 페이지가 곧 주문서다.

> 기준: 오너 결정(소셜 로그인 카카오·네이버만, 결제 토스페이먼츠 + 네이버페이 + 카카오페이, 기본 언어 한국어) · 말투 BRAND.md §3 · 화면 문구는 **시우 검수 전** · 2026-10-26

## 한 줄 구조

**카카오로 들어오면 주소까지 따라온다. 한 번 사면 다음부터는 "사기 → 결제하기" 두 번이다.**
- 로그인 = 카카오싱크(이름·전화·배송지까지 받음) 또는 네이버 로그인(이름·전화·이메일).
- 결제 = 토스페이먼츠 결제위젯 하나 안에 **브랜드페이(우리 간편결제, 원터치)** + 카카오페이 + 네이버페이 + 카드.
- 재구매 = 하단 시트 한 장. 지난번 주소, 지난번 결제수단 그대로.

## 1. 클릭 수

| 경우 | 흐름 | 탭 | 입력 |
|---|---|---|---|
| 첫 구매, 카카오 | 사기 → 카카오로 계속 → (카카오) 동의하고 계속 → 결제하기 → (카카오페이·브랜드페이) 승인 | 5 | 0 |
| 첫 구매, 네이버 | 사기 → 네이버로 계속 → (네이버) 동의 → 주소 찾기 → 주소 고르기 → 결제하기 → 승인 | 7 | 2 (검색어, 상세주소) |
| 재구매, 브랜드페이 원터치 | 사기 → 결제하기 | **2** | 0 |
| 재구매, 카카오·네이버페이 | 사기 → 결제하기 → (앱) 승인 | 3 | 0 |

- 로그인은 90일 유지한다. 재구매 때 로그인 화면이 다시 뜨면 두 번이 아니다.
- 카카오 로그인 사용자는 결제수단 기본값이 카카오페이, 네이버는 네이버페이. 브랜드페이를 한 번 등록하면 그게 기본값이 된다.

## 2. 화면과 문구

모든 화면은 세로 폰 한 손 기준. 버튼은 하단 고정 하나, 엄지 자리.

**A. 상품 페이지 (하단 고정)**
- 버튼: `28,000원 · 사기` (금액은 판매가 정해지면. 배송비 포함 총액을 버튼에 쓴다)
- 버튼 위 작은 줄: `배송비 포함이에요.`
- 수량은 버튼 왼쪽 `− 1 +`. 기본 1.
- 보조: `담아 두기` (텍스트 링크)

**B. 로그인 시트 (로그인 안 됐을 때만, 아래에서 올라옴)**
- 제목: `누군지만 알려 주세요.`
- 버튼: `카카오로 계속` (노랑) / `네이버로 계속` (초록)
- 작은 줄: `주소랑 연락처는 알아서 채워 둘게요.`
- 카카오 동의 거절하고 돌아오면: `괜찮아요. 네이버로 해도 돼요.`

**C. 주문서 (첫 구매, 한 화면)**
- 배송지 카드: `받는 분` 이름 · 전화 / 주소 두 줄 / 오른쪽 `바꾸기`
- 주소가 없으면(네이버) 카드 자리에 버튼: `어디로 보낼까요?` → 주소 찾기
- 배송 메모 칩: `문 앞` `경비실` `택배함` `직접 쓸게요` (기본: 문 앞)
- 결제수단: 토스 결제위젯 영역. 브랜드페이 줄 문구: `한 번 등록하면 다음부턴 바로 결제돼요.`
- 동의: 위젯 동의 영역(renderAgreement) 그대로.
- 버튼: `28,000원 결제하기`

**D. 주문 완료**
- `주문했어요.`
- `도착하면 한 번 뿌려 봐요.`
- 첫 구매일 때만: `다음엔 두 번이면 끝나요.`
- 버튼: `주문 보기`

**E. 재구매 시트 (로그인 + 배송지 있음 → "사기" 누르면 바로 이 시트)**
- 제목: `지난번처럼 보낼게요.`
- 줄 셋: 주소 한 줄 · 결제수단 한 줄 (`suaci 바로결제 · 신한 1234`) · 배송 메모
- 각 줄 오른쪽 `바꾸기`
- 버튼: `28,000원 결제하기`

**에러·복귀 문구**
| 상황 | 문구 |
|---|---|
| 결제창에서 취소하고 돌아옴 | `결제를 멈췄어요. 적은 건 그대로 있어요.` |
| 카드 승인 실패 | `카드사에서 안 됐대요. 다른 걸로 해 볼까요?` |
| 앱 전환 뒤 안 돌아옴, 다음 방문 | 상단 띠 `아까 하던 주문, 이어서 할까요?` `이어서` |
| 주소 검색 결과 없음 | `도로명이나 건물 이름으로 찾아봐요.` |
| 상세주소 비움 | `동·호수까지 적어 주세요. 없으면 '없음'도 돼요.` |
| 전화번호 형식 | `숫자만 넣어 주세요. 하이픈은 알아서 넣을게요.` |
| 품절 | `지금은 다 나갔어요.` + `들어오면 알려 줘요` (본인이 누를 때만) |
| 서버 오류 | `잠깐 막혔어요. 한 번만 다시 눌러 주세요.` |
| 담아 둔 게 있음, 재방문 | 상단 작은 줄 `담아 둔 게 있어요.` |

## 3. 정했다 (이유 한 줄씩)

1. **비회원 구매는 1차에 열지 않는다.** 카카오·네이버 한 번 탭이 비회원 폼(이름·전화·주소·주문 비밀번호)보다 짧고, 비회원은 재구매 두 번과 주소 저장을 못 한다. 로그인 시트 이탈률이 30%를 넘으면 연다.
2. **이메일·비밀번호 가입은 화면에서 뺀다.** 오너 결정이 카카오·네이버만이고, 입력 칸이 이탈의 첫 원인이다. 백엔드 코드는 지우지 않고 숨긴다.
3. **카카오는 카카오싱크로, 배송지를 첫 동의창에 선택 항목으로 넣는다.** 동의창은 한 번이어야 한다. 결제 직전 두 번째 동의창은 이탈 지점이다. 거절하면 그때만 주소 찾기를 띄운다.
4. **네이버는 이름·휴대전화·이메일만.** 네이버 로그인은 배송지를 주지 않는다. 첫 주문 한 번만 주소를 찾는다.
5. **결제는 토스 결제위젯 하나에 브랜드페이 + 카카오페이 + 네이버페이 + 카드.** 결제 화면이 하나여야 개발도, 고객도 헷갈리지 않는다.
6. **브랜드페이 원터치를 켠다(고객이 끌 수 있음).** 토스 자체 이상거래 탐지가 안전하다고 본 결제는 비밀번호 없이 끝난다. 쿠팡 원터치와 같은 구조다. 수수료 +1.0%는 재구매 두 번과 바꿀 값이다.
7. **결제수단은 위젯의 customerKey(=userId)로 기억한다.** 위젯이 재방문 고객의 지난 결제수단을 미리 골라 준다. 우리가 따로 저장하지 않는다.
8. **카드 정보는 우리 서버에 남기지 않는다.** 토스가 보관한다. 우리는 "신한 1234" 같은 표시용 이름만 받는다.
9. **장바구니 리마인드 메시지는 보내지 않는다.** BRAND.md: 구매·할인으로 재촉하지 않는다. 재방문 때 작은 줄 하나로 충분하다.
10. **재구매는 주문서 페이지가 아니라 하단 시트.** 페이지 이동이 없어야 두 번이 된다.
11. **주소 검색은 카카오 우편번호 서비스를 레이어(임베드)로.** 팝업은 카카오톡·인스타 인앱 브라우저에서 막힌다.
12. **주문은 결제 전 30분 보류(pending), 같은 idempotencyKey로 재시도.** 결제창에서 돌아와도 같은 주문을 이어 가고, 두 번 결제되지 않는다.

## 4. 저장하는 것과 시점

| 언제 | 저장 | 비고 |
|---|---|---|
| 소셜 동의 직후 | userId, 로그인 수단(kakao·naver), 이름, 휴대전화, 이메일(있으면) | 카카오 전화번호 `+82 10-…` → `010-…`로 바꿔 저장 |
| 소셜 동의 직후(카카오, 배송지 동의 시) | 카카오 기본 배송지 1개 → 우리 기본 배송지 | 수령인·전화·우편번호(zone_number)·주소·상세주소 |
| 첫 주문에서 새 주소 입력 | 배송지 저장 + 기본 배송지 | 체크 `다음에도 여기로` 기본 켬 |
| 주문 생성 | 주소 스냅샷(이미 있는 ShippingAddressSnapshot), 배송 메모 | 나중에 주소를 바꿔도 지난 주문은 그대로 |
| 결제 성공 | 마지막 배송 메모, 결제 표시명 | 결제수단 자체는 토스(customerKey) |
| 탈퇴 | 개인정보 삭제 | 주문·결제 기록은 전자상거래법 5년 보관 |

- 마케팅 수신 동의는 따로, 기본 꺼짐. 결제 흐름 안에서 묻지 않는다.
- 개인정보 처리방침에 넣을 것: 소셜 로그인으로 받는 항목, 배송사 제공, 토스페이먼츠 위탁.

## 5. 이탈 지점별 대책

| 지점 | 대책 |
|---|---|
| 총액이 늦게 보임(이탈 1위 원인, 추가 비용) | 상품 페이지 버튼에 배송비 포함 총액 |
| 로그인 | 시트 한 장, 버튼 둘. 입력 칸 0. 거절해도 다른 쪽 안내 |
| 주소 검색 | 레이어 임베드, 고르면 상세주소 칸에 바로 커서, `없음` 허용 |
| 입력 오류 | 칸 바로 아래 한 줄, 입력값 유지, 전화번호 자동 하이픈, 숫자 키패드 |
| 결제창 이탈 | 주문서로 복귀, 값 그대로, 같은 주문 이어서. 앱 전환 뒤 안 돌아오면 다음 방문 상단 띠 |
| 결제 실패 | 원인 한 줄 + 다른 수단 바로 고르기 |
| 장바구니 잔존 | 로그인 고객은 서버, 비로그인은 기기 저장. 로그인하면 합친다. 재방문 때 작은 줄 |
| 인앱 브라우저(카카오톡·인스타) | 카카오 로그인은 카카오톡 인앱에서 그대로 된다. 결제 앱 전환은 인앱별로 실기기 테스트 |
| 세션 만료 | 로그인 90일 유지. 만료되면 시트에서 같은 수단 한 번 탭 |

## 6. 모바일 우선 규칙

- 한 화면에 결정 하나. 하단 고정 버튼 하나.
- 입력 칸 글자 16px 이상(iOS 확대 방지), `autocomplete`·`inputmode` 속성(이름 `name`, 전화 `tel`, 우편번호 `postal-code`).
- 키보드가 올라와도 결제 버튼이 가려지지 않게.
- 데스크톱은 같은 흐름을 가운데 좁은 칸(최대 480px)으로.

## 7. 개발 메모

- 지금 코드: 홈페이지 `checkout`·`orders` 페이지, API의 address·cart·order·payment 도메인, Cognito 이메일 로그인이 있다. 주문은 `addressId + idempotencyKey`, 결제 승인은 토스 `paymentKey + amount`로 이미 맞춰져 있다.
- 추가: 카카오·네이버 OAuth(백엔드가 인가 코드를 받아 사용자 정보 조회 → Cognito 사용자 연결), 카카오 배송지 조회(`GET /v2/user/shipping_address`), 재구매 시트, 결제위젯 customerKey = userId, 브랜드페이 리다이렉트 처리(`code`, `customerKey` 확인 → Access Token).
- 네이버 로그인은 OIDC가 아니라 Cognito 기본 연동이 안 될 수 있다. 백엔드 직접 처리로 본다.

## 오너에게 남긴 것

판매가와 배송비. 버튼에 총액을 써야 해서, 정해지면 A·C·E 버튼 숫자만 바꾼다.
브랜드페이 이름. 지금은 `suaci 바로결제`로 적었다. 이름은 브랜드 판단이라 시우가 정한다.

참고: 토스페이먼츠 브랜드페이·결제위젯 문서, 카카오 로그인 REST API(배송지)·동의항목 문서, Shopify Shop Pay 도움말, 쿠페이 원터치 보도, Baymard 체크아웃 조사. 네이버 개발자센터 문서는 직접 열지 못했다.
